1"""The app's top menu bar — the horizontal replacement for the former sidebar. 

2 

3Every group that used to be an ``st.sidebar`` section is now a **popover** in one 

4row directly under the header, and nothing in the app writes to ``st.sidebar`` 

5any more (so Streamlit draws no sidebar chrome at all and the main content gets 

6the full page width). 

7 

8**Why popovers and not ``st.dialog``.** A dialog body only executes while the 

9dialog is open, but these panels are not passive display — several of them drive 

10``app.prepare_data`` on every rerun, and Streamlit drops the state of a widget 

11that does not render. A popover is a plain ``DeltaGenerator`` — it executes every 

12run and can be filled long after later elements were written, which is exactly 

13the ``st.sidebar`` semantics being replaced. That is what keeps this a host swap 

14rather than a restructure: ``main`` still reserves a slot here and downstream 

15code still fills it by ``host=``. 

16 

17**UX-100 made 💾 Session a modal, opened from the nav.** UX-63 had made it a 

18nav *page*; once UX-96 had cut it down to four short blocks, a whole top-level 

19destination for them was more chrome than they were worth — a page you navigate 

20*away* from is the wrong shape for "check the recovery cache, then carry on". 

21It is now exactly what ❓ Help's entries are: a nav entry that **arms a dialog 

22and bounces straight back** to the view you were on, so the panel opens over 

23your work. See :func:`render_nav`, which serves both, and 

24``app._session_dialog``, which is the body. 

25 

26That shape has one consequence the panels had to be written for: **a dialog body 

27is a fragment**. It runs only while the dialog is open, and Streamlit drops a 

28widget's key at the end of any run in which it did not render — so every widget 

29in there either re-seeds from a durable value each render (the persistence pause 

30toggle and the 🐛 Debug gate both do) or holds nothing worth keeping (the 

31buttons, the JSON download). It also means an interaction inside the dialog 

32reruns *the dialog*, not ``main`` — which is why restoring a backup from in 

33there ends in an explicit ``st.rerun(scope="app")``, and why the two 

34confirmations are inline rows rather than nested dialogs (Streamlit allows no 

35dialog inside a dialog). 

36 

37**DATA-26 took two groups off this bar.** ⚙️ Configure and 🧹 Preprocessing are 

38now sections of the **Data** page (``constants._VIEW_DATA``), because setting a 

39dataset up was split across a menu group and a subtab on the other side of the 

40app. Their widgets keep the every-run execution the popovers gave them: the page 

41container is built every run and merely hidden off-screen when another view is 

42active (``constants.DATA_PAGE_OFFSCREEN_KEY`` + the ``display: none`` rule in 

43``styles.py``). What is left is genuinely session-wide and lives in the 💾 Session dialog: 

44🗄️ Automatic recovery · ⬇️ JSON backup · ♻️ Reset · 🐛 Debug tools. 

45 

46**Consequences for panel authors.** A popover nests neither an expander nor 

47another popover, so a group that used to wrap itself in 

48``st.sidebar.expander("<title>")`` now renders **bare** into its slot — the 

49popover trigger *is* the disclosure, and repeating the title inside it would 

50just be the label twice. See ``app._preprocessing_settings``, 

51``app._render_recovery_cache_panel`` and ``tabs._render_save_restore_expander``. 

52 

53Streamlit 1.62 owns the viewport-aware maximum width; ``styles.py`` keeps only 

54the preferred 28 rem minimum for roomy desktop panels. 

55"""

156def close_open_popovers() -> None: 

157 """Dismiss whichever menu popover is open, client-side. 

158 

159 A popover's open/closed state lives in the browser, so a server callback can 

160 arm a dialog but cannot close the ❓ Help popover the button was inside — 

161 leaving the popover panel floating on top of the modal it just opened. Call 

162 this from a dialog body: it clicks the expanded trigger, which toggles it 

163 shut. Retried, because a click during React hydration is silently lost. 

164 

165 Same trick as ``tour``'s tutorial-chooser closer, generalized: match any 

166 expanded popover trigger rather than one by label. 

167 """ 

168 from scanpath_studio.html_embed import embed_html_iframe 

169 

170 embed_html_iframe( 

171 """<script> 

172 (function () { 

173 const doc = window.parent.document; 

174 let tries = 0; 

175 (function closePopover() { 

176 const trigger = doc.querySelector( 

177 '[data-testid="stPopover"] button[aria-expanded="true"]'); 

178 if (trigger) { trigger.click(); return; } 

179 if (++tries < 20) setTimeout(closePopover, 50); 

180 })(); 

181 })(); 

182 </script>""", 

183 height=0, 

184 )

210 """Navigate to ``view`` programmatically. Reruns; does not return.

248def render_nav() -> str: 

249 """Draw Streamlit's native top nav and return the active view. 

250 

251 Uses ``st.navigation(position="top")`` — the platform's own navigation, 

252 rendered into the header strip beside the toolbar, so it costs no page 

253 height and looks like Streamlit rather than like an app control. 

254 

255 **``main_nav`` is kept as a mirror, not the source of truth.** The router 

256 owns the selection, but several places still *write* ``main_nav`` to request 

257 a view (``_go_corpus`` / ``_go_scanpath``, ``tour`` when a step drives the 

258 app to another view, and ``persistence`` restoring the view you were last 

259 on) — including from ``on_click`` callbacks, where ``st.switch_page`` is not 

260 allowed. So each run reconciles, then writes the resolved view back, and 

261 every existing reader of ``main_nav`` — the tour, ``persistence``, 

262 ``_active_view`` — keeps working unchanged. 

263 

264 The reconciliation turns on ``_nav_mirrored``: the value this function wrote 

265 last run. Without it the two directions are indistinguishable and the nav 

266 is unusable — clicking "Corpus Analysis" makes ``main_nav`` (still holding 

267 last run's "Scanpath") disagree with the router, which reads as a request to 

268 go *back*, and the click bounces. Comparing against what we last mirrored 

269 separates them: ``main_nav`` still equal to it means nobody asked for 

270 anything and the router simply moved (the user clicked); ``main_nav`` 

271 changed out from under it is a genuine request, honoured by switching — 

272 which reruns, and next run the two agree and it stops. 

273 """ 

274 _PAGES.clear() 

275 for view, (label, icon, url_path) in _NAV_PAGES.items(): 

276 _PAGES[view] = st.Page( 

277 _unused_page_body, 

278 title=label, 

279 icon=icon, 

280 url_path=url_path, 

281 default=view == _VIEW_SCANPATH, 

282 ) 

283 # UX-65: a *dict* of sections. The entries under the empty-string key are 

284 # drawn first, at the top level; every other key becomes a collapsible item 

285 # — Streamlit's own documented behaviour for `position="top"`, so ❓ Help 

286 # opens a menu with no CSS of ours. 

287 action_pages = { 

288 entry: st.Page(_unused_page_body, title=label, icon=icon, url_path=url_path) 

289 for entry, (label, icon, url_path) in { 

290 **_ACTION_PAGES, 

291 **_HELP_PAGES, 

292 }.items() 

293 } 

294 top_level = [*_PAGES.values()] + [ 

295 action_pages[entry] for entry in _ACTION_PAGES if entry in action_pages 

296 ] 

297 selected = st.navigation( 

298 { 

299 "": top_level, 

300 HELP_SECTION: [action_pages[entry] for entry in _HELP_PAGES], 

301 }, 

302 position="top", 

303 ) 

304 # An action entry is not a destination: arm its dialog and go straight back 

305 # to the view the user was on, so the modal opens over their work instead of 

306 # over an empty page. The bounce reruns, and next run the router has 

307 # re-selected that view, so nothing re-arms. 

308 chosen_action = next( 

309 (entry for entry, page in action_pages.items() if page.title == selected.title), 

310 None, 

311 ) 

312 if chosen_action is not None: 

313 _arm_help_action(chosen_action) 

314 back = st.session_state.get(_MIRROR_KEY) 

315 switch_to_view(back if back in _PAGES else _VIEW_SCANPATH) # reruns 

316 active = next( 

317 (view for view, page in _PAGES.items() if page.title == selected.title), 

318 _VIEW_SCANPATH, 

319 ) 

320 requested = st.session_state.get("main_nav") 

321 mirrored = st.session_state.get(_MIRROR_KEY) 

322 if requested in _PAGES and requested != active and requested != mirrored: 

323 st.session_state[_MIRROR_KEY] = requested 

324 switch_to_view(requested) # reruns 

325 st.session_state["main_nav"] = active 

326 st.session_state[_MIRROR_KEY] = active 

327 return active

330def render_top_menu( 

331 *, show_debug: bool = False, active_view: str | None = None 

332) -> TopMenu: 

333 """Draw the native top nav + the two menu pages, returning their slots. 

334 

335 Call this once, early in ``app.main`` — before any data loading, so the 

336 loaders' UI lands in the bar rather than after the page content. 

337 

338 **UX-63 made 💾 Session a nav page; UX-100 made it a dialog.** The nav's 

339 *views* are the three the work happens on — Scanpath · Corpus Analysis · 

340 Data — and 💾 Session sits beside them as an **action** entry, the same 

341 shape ❓ Help's Tutorials / FAQ / About already had: selecting it arms a 

342 modal and bounces the router back, so the panel opens over your work. UX-96 

343 had already cut the group to four short blocks, at which point a top-level 

344 destination for them was more chrome than they were worth. 

345 

346 So this function no longer builds the panel at all — ``app._session_dialog`` 

347 is its body, and what is left here is the title row and the notices strip. 

348 

349 Args: 

350 show_debug: Add the 🐛 Debug block. Only debug sessions want it 

351 (``debug_log.debug_enabled``). Carried on the returned 

352 :class:`TopMenu` so the dialog body does not resolve it a second 

353 time. 

354 active_view: The entry the nav currently has selected, from 

355 :func:`render_nav`. Accepted so callers that already resolved the 

356 view do not resolve it twice. 

357 

358 Returns: 

359 ``title`` — ``app._render_about_panel`` fills it — plus the main-area 

360 ``notices`` strip and the debug flag. 

361 """ 

362 if active_view is None: 

363 render_nav() 

364 title_col, _ = st.columns([4, 1], vertical_alignment="bottom") 

365 return TopMenu( 

366 notices=st.container(key=NOTICES_KEY), 

367 title=title_col, 

368 show_debug=show_debug, 

369 )
