1"""First-visit welcome tour. 

2 

3Two interchangeable styles, both introducing the app's main surfaces (data 

4sources, filters, viz controls, tabs, annotations) the first time a session 

5opens the app, re-playable any time via the sidebar's tutorial button: 

6 

7- ``"spotlight"`` (default): a floating card that walks through the *actual* 

8 UI — each step scrolls the target section into view and pulses an outline 

9 around it. Rendered by ``render_spotlight_tour()`` at the end of ``main()``. 

10- ``"dialog"``: a self-contained multi-step ``st.dialog`` modal. 

11 

12Switch styles with the ``TOUR_STYLE`` constant below. 

13 

14Mechanics worth knowing before editing: 

15 

16- Both styles run as *fragments*: Back/Next clicks rerun only the tour body, 

17 so navigation is instant instead of waiting for a full-app rerun (which 

18 re-renders the heavy plot embeds, ~10 s). The spotlight's Done / ✕ just 

19 clear ``tour_mode`` — the fragment then renders nothing and the card + 

20 highlight CSS disappear with it, again with no full rerun. The dialog's 

21 Skip/Done close the modal client-side (``_close_dialog_clientside``). 

22- The spotlight card streams to the browser *before* the heavy first-load 

23 work, but its Done / ✕ are ordinary Streamlit buttons — a click only 

24 schedules a rerun, which can't run until that ~10 s load finishes, so the 

25 card + dimming backdrop would linger the whole time. A same-origin listener 

26 (``_dismiss_listener_script``) hides them instantly on click; the button's 

27 native click still clears ``tour_mode`` once Streamlit catches up. 

28- Spotlight targets are ``.st-key-tour_grp_*`` classes from keyed wrapper 

29 containers around the sidebar sections (app.py / controls.py / 

30 annotations.py) plus Streamlit's stable ``data-testid``/``data-baseweb`` 

31 attributes for the tab strip. Keep ``_SPOTLIGHT_STEPS`` in sync with them. 

32- ``tour_seen`` is set **before** the tour is shown, not when it's finished. 

33 For the dialog style, setting it on Done only would make an X-dismissal 

34 re-open the modal on the very next widget interaction (any full rerun 

35 re-calls ``maybe_show_welcome_tour``), making the X appear broken. 

36- The tour is suppressed for embeds (``?embed=true``) and deep links 

37 (``?source=…&participant=…``): those sessions arrive mid-workflow from an 

38 external tool and shouldn't be greeted by a tutorial. 

39- **"Don't show this again" (UX-12)** persists in a first-party *cookie*, not 

40 session state — there are no user accounts, and session state dies with the 

41 tab. A cookie is the one browser-side store Python can also *read* 

42 (``st.context.cookies``); ``localStorage`` would need a bidirectional custom 

43 component to get the value back to the server. The checkbox writes it via a 

44 same-origin script (``_tour_optout_script``); ``tour_opted_out()`` reads it. 

45 The replay button ignores the opt-out entirely, so the tour is never lost. 

46- **The FAQ (UX-15)** is the other half of the sidebar's Help group: a short 

47 ``st.dialog`` of recurring questions (``render_faq_button``), deliberately 

48 kept to a handful of answers with the complete version on the docs site 

49 (``docs/faq.md``). It is armed exactly like the tour — the button's 

50 ``on_click`` sets a request flag that ``maybe_show_faq`` serves early in 

51 ``main()`` — because the button renders at the *bottom* of ``main()``: 

52 opening the dialog from its return value made the modal wait out the whole 

53 rerun (~10 s of plot embeds) before appearing. 

54"""

111def _close_dialog_clientside() -> None: 

112 """Hide the open dialog instantly by clicking its own ✕ from a tiny script. 

113 

114 The documented way to close a dialog programmatically is a full-app 

115 ``st.rerun()`` — but on this app a full rerun re-renders the heavy plot 

116 embeds, so the modal lingered ~10 s after Skip/Done. Instead, run inside 

117 the (fast) dialog-fragment rerun and click the dialog's close button: 

118 the modal hides client-side immediately and Streamlit's normal dismiss 

119 handling syncs state in the background. ``st.iframe`` embeds are 

120 same-origin, so the script can reach the parent document. 

121 """

123 """<script> 

124 window.parent.document 

125 .querySelector('div[role="dialog"] button[aria-label="Close"]') 

126 ?.click(); 

127 </script>""", 

128 height=0, 

129 )

410def _dismiss_listener_script( 

411 selector: str | None, 

412 exit_keys: tuple[str, ...] = ("tour_sp_done", "tour_sp_close"), 

413) -> str: 

414 """JS that lets Done / ✕ close the tour *instantly*, even mid-load. 

415 

416 The card streams to the browser early (before the ~10 s data/plot work), 

417 but its Done / ✕ are ordinary Streamlit buttons: a click only schedules a 

418 rerun, which Streamlit can't process until the in-flight first run 

419 finishes — so the card and its dimming backdrop linger for the whole load. 

420 

421 This same-origin script attaches a plain ``click`` listener to those 

422 buttons that hides the card, backdrop, and highlight outline immediately 

423 via an injected ``!important`` stylesheet — no server roundtrip. The 

424 button's native click still fires too, so ``_exit_spotlight`` runs whenever 

425 Streamlit catches up and clears ``tour_mode`` durably. Re-arming the tour 

426 re-renders this script, which first drops any stale hide style so the 

427 replayed card is visible. 

428 """ 

429 outline_clear = ( 

430 f"{selector} {{ outline: none !important; animation: none !important; }}" 

431 if selector 

432 else "" 

433 ) 

434 hide_css = ( 

435 ".st-key-tour_card, .tour-backdrop { display: none !important; } " 

436 + outline_clear 

437 ) 

438 btn_selectors = [f".st-key-{k} button" for k in exit_keys] 

439 return f"""<script> 

440 (function () {{ 

441 const doc = window.parent.document; 

442 doc.getElementById("tour-instant-hide")?.remove(); // clear stale hide 

443 const hide = () => {{ 

444 const s = doc.createElement("style"); 

445 s.id = "tour-instant-hide"; 

446 s.textContent = {hide_css!r}; 

447 doc.head.appendChild(s); 

448 doc.querySelectorAll(".tour-backdrop").forEach((e) => e.remove()); 

449 }}; 

450 let tries = 0; 

451 (function wire() {{ 

452 const btns = {btn_selectors!r} 

453 .map((sel) => doc.querySelector(sel)).filter(Boolean); 

454 if (!btns.length) {{ 

455 if (++tries < 20) setTimeout(wire, 100); 

456 return; 

457 }} 

458 btns.forEach((b) => {{ 

459 if (b.dataset.tourHideWired) return; 

460 b.dataset.tourHideWired = "1"; 

461 b.addEventListener("click", hide, {{ once: true }}); 

462 }}); 

463 }})(); 

464 }})(); 

465 </script>"""

469def render_spotlight_tour() -> None: 

470 """Floating tour card + pulsing highlight for the current spotlight step. 

471 

472 Call early in ``main()``, right after ``maybe_show_welcome_tour()``, so 

473 the card streams to the browser before the heavy data/plot work instead 

474 of seconds after the page opens. Replay clicks still activate it within 

475 the same run because the button arms the tour in its ``on_click`` 

476 callback (``_arm_tour``), which runs before the rerun starts. Runs as a 

477 fragment: Back/Next/close rerun only this function, so the highlight moves 

478 instantly and ✕ makes the card + CSS vanish without a full-app rerun 

479 (the fragment then renders nothing, which clears its previous elements). 

480 """ 

481 if st.session_state.get("tour_mode") != "spotlight": 

482 return 

483 n = len(_SPOTLIGHT_STEPS) 

484 step_idx = min(st.session_state.get("tour_step", 0), n - 1) 

485 step = _SPOTLIGHT_STEPS[step_idx] 

486 

487 # BUG-6: fall back to the app's brand blue (matches the pinned theme 

488 # `.streamlit/config.toml` primaryColor), never Streamlit's default red, so 

489 # the tour accent stays consistent even if the runtime doesn't expose the 

490 # theme option. 

491 accent = st.get_option("theme.primaryColor") or "#1f77b4" 

492 # Card colors follow the active theme when the runtime exposes it 

493 # (st.context.theme, Streamlit ≥1.46); default to light otherwise. 

494 theme = getattr(getattr(st, "context", None), "theme", None) 

495 is_dark = getattr(theme, "type", "light") == "dark" 

496 bg, border = ("#262730", "#41434e") if is_dark else ("#ffffff", "#d5d6d9") 

497 

498 highlight = "" 

499 if step["selector"]: 

500 highlight = f""" 

501{step["selector"]} {{ 

502 outline: 3px solid {accent}; 

503 outline-offset: 3px; 

504 border-radius: 0.5rem; 

505 animation: tour-pulse 1.6s ease-in-out infinite; 

506}} 

507@keyframes tour-pulse {{ 

508 0%, 100% {{ box-shadow: 0 0 0 0 color-mix(in srgb, {accent} 50%, transparent); }} 

509 50% {{ box-shadow: 0 0 14px 7px color-mix(in srgb, {accent} 25%, transparent); }} 

510}} 

511""" 

512 st.markdown( 

513 "<style>" 

514 + _CARD_CSS 

515 + f".st-key-tour_card {{ background: {bg}; border: 1px solid {border}; }}" 

516 + (_WELCOME_CSS if step_idx == 0 else "") 

517 + highlight 

518 + "</style>", 

519 unsafe_allow_html=True, 

520 ) 

521 if step_idx == 0: 

522 st.markdown('<div class="tour-backdrop"></div>', unsafe_allow_html=True) 

523 

524 with st.container(key="tour_card"): 

525 # Close (✕) in the top-right corner — exits the tour like "Exit"/"Done"

532 )

535 # to the original compact look via `.st-key-tour_card h2` in _CARD_CSS. 

536 st.markdown(f"## {step['title']}") 

537 st.markdown(step["body"])

577 if step["selector"]: 

578 # Bring the highlighted section into view. Same-origin iframe 

579 # trick as _close_dialog_clientside; no-op if the selector is 

580 # gone. Subtleties, all observed live: 

581 # - Sidebar steps first click Streamlit's expand control, since 

582 # tour sessions start with the sidebar collapsed 

583 # (spotlight_tour_pending → initial_sidebar_state). 

584 # - The find+scroll retries until the target is visible, riding 

585 # out the sidebar-expand animation. 

586 # - Match the first *visible* element, not the first match: 

587 # Streamlit keeps inactive tab panels laid out but 

588 # visibility-hidden, so a selector can hit an invisible 

589 # duplicate (e.g. the Raw Data panel's inner tab strip) and 

590 # scroll the page to nowhere. 

591 # - No scrollIntoView: smooth gets cancelled by Streamlit's 

592 # re-renders, and instant also scrolls the document, moving 

593 # the main column for sidebar targets. Instead, center the 

594 # target within its nearest scrollable ancestor only. 

595 # - Skip targets that are already fully on screen. 

596 # - The iframe stays INSIDE the fixed-position card: when it sat 

597 # at the bottom of the main column, its (re)mount could yank 

598 # the main scroller to the page bottom to reveal it. 

599 # Most keyed-wrapper targets live in the sidebar, but some (the viz 

600 # controls now sit in the Scanpath rail) are in the main area — let a 

601 # step opt out explicitly; otherwise fall back to the prefix rule. 

602 in_sidebar = step.get( 

603 "in_sidebar", 

604 bool(step["selector"]) 

605 and step["selector"].startswith(".st-key-tour_grp_"), 

606 ) 

607 embed_html_iframe( 

608 f"""<script> 

609 (function () {{ 

610 const doc = window.parent.document; 

611 const win = doc.defaultView; 

612 const findVisible = () => 

613 [...doc.querySelectorAll({step["selector"]!r})].find((e) => {{ 

614 const r = e.getBoundingClientRect(); 

615 if (r.width === 0 || r.height === 0) return false; 

616 const cs = win.getComputedStyle(e); 

617 return cs.visibility !== "hidden" && cs.display !== "none"; 

618 }}); 

619 let tries = 0; 

620 (function attempt() {{ 

621 if ({str(in_sidebar).lower()}) {{ 

622 // The collapsed sidebar keeps its layout (nonzero 

623 // rects), so gate on aria-expanded, not on 

624 // findVisible(). Retries ride out hydration. 

625 const sb = doc.querySelector( 

626 'section[data-testid="stSidebar"]'); 

627 if (sb && sb.getAttribute("aria-expanded") !== "true") {{ 

628 doc.querySelector( 

629 'button[data-testid="stExpandSidebarButton"]' 

630 )?.click(); 

631 if (++tries < 20) setTimeout(attempt, 150); 

632 return; 

633 }} 

634 }} 

635 const el = findVisible(); 

636 if (!el) {{ 

637 if (++tries < 20) setTimeout(attempt, 150); 

638 return; 

639 }} 

640 for (let box = el.parentElement; box; box = box.parentElement) {{ 

641 const cs = win.getComputedStyle(box); 

642 if (/(auto|scroll|overlay)/.test(cs.overflowY) 

643 && box.scrollHeight > box.clientHeight + 4) {{ 

644 const r = el.getBoundingClientRect(); 

645 const b = box.getBoundingClientRect(); 

646 const slack = 8; 

647 if (r.top >= b.top - slack 

648 && r.bottom <= b.top + box.clientHeight + slack) {{ 

649 return; // already visible within its scroller 

650 }} 

651 box.scrollTop += r.top - b.top 

652 - Math.max(0, (box.clientHeight - r.height) / 2); 

653 return; 

654 }} 

655 }} 

656 }})(); 

657 }})(); 

658 </script>""", 

659 height=0, 

660 ) 

661 else: 

662 # Welcome step: close the sidebar so the centered card sits over 

663 # a quiet page. initial_sidebar_state="collapsed" (configure_page) 

664 # covers fresh visitors, but the frontend's per-tab stored sidebar 

665 # state overrides it for returning tabs — so also click the 

666 # collapse control. Retries because a click during initial React 

667 # hydration is silently lost. The first sidebar step reopens it. 

668 embed_html_iframe( 

669 """<script> 

670 (function () { 

671 const doc = window.parent.document; 

672 let tries = 0; 

673 (function attempt() { 

674 const sb = doc.querySelector('section[data-testid="stSidebar"]'); 

675 if (!sb || sb.getAttribute("aria-expanded") !== "true") return; 

676 (doc.querySelector( 

677 '[data-testid="stSidebarCollapseButton"] button') 

678 || doc.querySelector('section[data-testid="stSidebar"]' 

679 + ' [data-testid="stBaseButton-headerNoPadding"]')) 

680 ?.click(); 

681 if (++tries < 25) setTimeout(attempt, 200); 

682 })(); 

683 })(); 

684 </script>""", 

685 height=0,
