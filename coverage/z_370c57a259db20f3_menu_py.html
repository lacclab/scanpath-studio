1"""The app's header: the native top nav, the title row and the notices strip. 

2 

3Nothing in the app writes to ``st.sidebar``, so Streamlit draws no sidebar 

4chrome and the main content gets the full page width. 

5 

6**The nav** (:func:`render_nav`) is Streamlit's own 

7``st.navigation(position="top")``: three **views** — 🗺️ Scanpath · 📊 Corpus 

8Analysis · 🗂️ Data — and a ❓ Help section of **action** entries (Tutorials, 

9FAQ, About, Send feedback; Debug opens from the foot of About). Selecting an action arms a dialog and bounces the router 

10straight back to the view you were on, so the modal opens over your work. 

11 

12Session-wide tools are not on the bar but where each is used: what the 

13recovery cache holds at the foot of the Data page 

14(``app._render_saved_here_section``), the settings file on 🗺️ Scanpath → 

15🔗 Share → File (``tabs.render_settings_file``), and the annotations' export on 

16🗂️ Data → Annotations. 

17 

18The Data page's sections run on every run: the page container is built every 

19run and hidden off-screen when another view is active 

20(``constants.DATA_PAGE_OFFSCREEN_KEY`` + the ``display: none`` rule in 

21``styles.py``), because Streamlit drops the state of a widget that does not 

22render and several of them drive ``app.prepare_data``. 

23"""

42#: The spotlight tour's selector for the navigation. Streamlit's own top nav has 

43#: no key of ours to hang a ``.st-key-*`` class on, so the step points at the

48#: "Scanpath", not "Scanpath Visualization" — because the nav sits in Streamlit's 

49#: header strip beside the toolbar, where a long label crowds it. The exception 

50#: is *Data Management*, which matches the page's own header. 

51#: **Data comes last** even though setting a dataset up comes first in time: it 

52#: is visited occasionally, while the two analysis views are where the work

61#: These are not views. Each one opens a dialog over whatever you were already 

62#: looking at — see :func:`render_nav` for the bounce that makes that work. 

63#: Documentation is absent on purpose: ``st.Page`` cannot be a URL, and the

65_HELP_PAGES = {

119def _unused_page_body() -> None: # pragma: no cover - never executed 

120 """Placeholder body for the ``st.Page`` objects. 

121 

122 ``st.navigation`` is used here only to *render* the nav and report which 

123 entry is selected — we never call ``.run()``, because ``app.main`` owns 

124 the dispatch (it has to: the view bodies close over frames the long prelude

131def switch_to_view(view: str) -> None: 

132 """Navigate to ``view`` programmatically. Reruns; does not return. 

133 

134 The router owns the selection, so writing ``main_nav`` is not enough on 

135 its own — this is what actually moves the nav. Not callable from a widget 

136 callback (Streamlit forbids ``st.switch_page`` there); callbacks should write 

137 ``main_nav`` and let :func:`render_nav`'s reconciliation do the switch on the 

138 next run. 

139 """ 

140 page = _PAGES.get(view) 

141 if page is not None: 

142 st.switch_page(page)

170def render_nav() -> str: 

171 """Draw Streamlit's native top nav and return the active view. 

172 

173 Uses ``st.navigation(position="top")`` — the platform's own navigation, 

174 rendered into the header strip beside the toolbar, so it costs no page 

175 height and looks like Streamlit rather than like an app control. 

176 

177 **``main_nav`` is kept as a mirror, not the source of truth.** The router 

178 owns the selection, but several places *write* ``main_nav`` to request 

179 a view (``url_state._go_scanpath`` / ``_go_data``, ``tour`` when a step drives the 

180 app to another view, and ``persistence`` restoring the view you were last 

181 on) — including from ``on_click`` callbacks, where ``st.switch_page`` is not 

182 allowed. So each run reconciles, then writes the resolved view back for 

183 every reader of ``main_nav`` — the tour, ``persistence``. 

184 

185 The reconciliation turns on ``_nav_mirrored``: the value this function wrote 

186 last run. Without it the two directions are indistinguishable and the nav 

187 is unusable — clicking "Corpus Analysis" makes ``main_nav`` (still holding 

188 last run's "Scanpath") disagree with the router, which reads as a request to 

189 go *back*, and the click bounces. Comparing against what we last mirrored 

190 separates them: ``main_nav`` still equal to it means nobody asked for 

191 anything and the router simply moved (the user clicked); ``main_nav`` 

192 changed out from under it is a genuine request, honoured by switching — 

193 which reruns, and next run the two agree and it stops. 

194 """ 

195 _PAGES.clear() 

196 for view, (label, icon, url_path) in _NAV_PAGES.items(): 

197 _PAGES[view] = st.Page( 

198 _unused_page_body, 

199 title=label, 

200 icon=icon, 

201 url_path=url_path, 

202 default=view == _VIEW_SCANPATH, 

203 ) 

204 # A *dict* of sections. The entries under the empty-string key are 

205 # drawn first, at the top level; every other key becomes a collapsible item 

206 # — Streamlit's own documented behaviour for `position="top"`, so ❓ Help 

207 # opens a menu with no CSS of ours. 

208 action_pages = { 

209 entry: st.Page(_unused_page_body, title=label, icon=icon, url_path=url_path) 

210 for entry, (label, icon, url_path) in _HELP_PAGES.items() 

211 } 

212 selected = st.navigation( 

213 { 

214 "": [*_PAGES.values()], 

215 HELP_SECTION: [action_pages[entry] for entry in _HELP_PAGES], 

216 }, 

217 position="top", 

218 ) 

219 # An action entry is not a destination: arm its dialog and go straight back 

220 # to the view the user was on, so the modal opens over their work instead of 

221 # over an empty page. The bounce reruns, and next run the router has 

222 # re-selected that view, so nothing re-arms. 

223 chosen_action = next( 

224 (entry for entry, page in action_pages.items() if page.title == selected.title), 

225 None, 

226 ) 

227 if chosen_action is not None: 

228 _arm_help_action(chosen_action) 

229 back = st.session_state.get(_MIRROR_KEY) 

230 switch_to_view(back if back in _PAGES else _VIEW_SCANPATH) # reruns 

231 active = next( 

232 (view for view, page in _PAGES.items() if page.title == selected.title), 

233 _VIEW_SCANPATH, 

234 ) 

235 requested = st.session_state.get("main_nav") 

236 mirrored = st.session_state.get(_MIRROR_KEY) 

237 # On a session's first run (nothing mirrored yet), a page the URL names — 

238 # `/data`, `/corpus-analysis` — is where the user asked to go, and wins over 

239 # the view the recovery cache restored into `main_nav`. Only the bare root 

240 # (the default page) resumes the last view. 

241 url_named_page = _MIRROR_KEY not in st.session_state and active != _VIEW_SCANPATH 

242 if ( 

243 requested in _PAGES 

244 and requested != active 

245 and requested != mirrored 

246 and not url_named_page 

247 ): 

248 st.session_state[_MIRROR_KEY] = requested 

249 switch_to_view(requested) # reruns 

250 st.session_state["main_nav"] = active 

251 st.session_state[_MIRROR_KEY] = active 

252 return active

255def render_top_menu(*, active_view: str | None = None) -> TopMenu: 

256 """Draw the native top nav, then the title row and the notices strip. 

257 

258 Call this once, early in ``app.main`` — before any data loading, so load 

259 warnings land in the notices strip rather than after the page content. 

260 

261 Args: 

262 active_view: The entry the nav currently has selected, from 

263 :func:`render_nav`. Accepted so callers that already resolved the 

264 view do not resolve it twice. 

265 

266 Returns: 

267 ``title`` — ``app._render_about_panel`` fills it — and ``aside`` (the 

268 mode switch's slot), plus the main-area ``notices`` strip. 

269 """ 

270 if active_view is None: 

271 render_nav() 

272 title_col, aside_col = st.columns([4, 1], vertical_alignment="bottom") 

273 return TopMenu( 

274 notices=st.container(key=NOTICES_KEY), 

275 title=title_col, 

276 aside=aside_col, 

277 )
