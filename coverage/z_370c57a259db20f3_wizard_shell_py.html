1"""The Add-dataset wizard's shell: step registry, status, accordion, progress 

2and navigation (DATA-22). 

3 

4Knows nothing about columns or dataframes — ``wizard.py`` keeps the step bodies 

5and finalize. What lives here is the *chrome*: which steps exist, what each one's 

6status badge is, which one is open, and the buttons that move between them. 

7 

8**The one rule that makes the accordion work.** A step's open flag 

9(``wiz_open_<id>``) is written *only* by `seed_open_step`, `go_to_step`, 

10the guide, and `seed_open_step`. Nothing inside a step body may touch it. The old wizard recomputed ``expanded=`` from whether the step was 

11"done", so the first pick in a step flipped ``done`` and the expander collapsed 

12under the user's cursor mid-edit (DATA-19 patched that with a one-shot marker 

13that survived exactly one rerun; this replaces the mechanism rather than 

14patching it again). Here the flag is a keyed-expander widget value: the user's 

15own click owns it, and code only moves it on an explicit navigation. 

16 

17**A keyed expander's label and icon must be CONSTANT.** Changing either remounts 

18the widget at its default — i.e. collapsed — on the very next run, no matter what 

19its key holds. That is not a theory: an upload flips step 1 from *action* to 

20*done*, and while the status badge was passed as ``icon=`` the step slammed shut 

21the instant the file finished uploading, which is exactly the DATA-19 symptom 

22this design set out to remove, arriving through a different door. The badge 

23therefore lives on the progress chips (`render_progress`) and nowhere else; the 

24expander header carries only the fixed number + title. Reproduced and pinned by 

25``tests/test_wizard_helpers.py::TestWizardAccordion:: 

26test_a_changing_header_would_collapse_a_keyed_expander``. 

27 

28**Step bodies must never be gated on the expander being open.** Streamlit drops 

29a widget's key from session state at the end of any run in which the widget did 

30not render, and ``controls.column_mapping_ui`` builds its ``col_map_*`` widgets 

31without ``persist_state`` — so a collapsed-and-therefore-unrendered step would 

32silently discard its mapping. Collapsed-but-rendered is correct; see the comment 

33at the `step_panel` call sites in ``wizard.py``. 

34"""

84#: to five — flat and same-size, not the old per-step expanders. UX-114 folded 

85#: "Keep extra fields" back into "Map data fields" (each table's own keep 

86#: picker now sits directly under that table's own mapping — a cross-table 

87#: pick was a second, confusing decision), leaving four. UX-129 folded "Map 

88#: data fields" itself into "Upload data tables" — UX-122/127 had already

176def numbered( 

177 steps: Iterable[WizardStep], shown: Iterable[str] 

178) -> dict[str, WizardStep]: 

179 """``steps`` renumbered 1..n over the subset named in ``shown``. 

180 

181 Returns a mapping keyed by step id, so a caller can draw a part without 

182 knowing where in the sequence it landed. Ids in ``shown`` that no step 

183 declares are ignored; steps not in ``shown`` are absent from the result, 

184 which is what a caller should check rather than tracking the condition 

185 twice. 

186 """ 

187 keep = set(shown) 

188 out: dict[str, WizardStep] = {} 

189 for step in steps: 

190 if step.id not in keep: 

191 continue 

192 out[step.id] = WizardStep( 

193 step.id, len(out) + 1, step.title, step.caption, step.required 

194 ) 

195 return out

208def part( 

209 host, 

210 step: WizardStep, 

211 *, 

212 status: StepStatus | None = None, 

213 trailing=None, 

214 note: str = "", 

215): 

216 """One linear part of the wizard: a minimal headline, then its body. 

217 

218 UX-53 r8. The parts run in a fixed order — there is nothing to map before a 

219 file is read — so this is a *label*, not navigation: no expander, no chips, 

220 no open state, and therefore none of the DATA-19 / DATA-22 collapse 

221 machinery. It costs one line, which is the point; the previous shapes spent 

222 a header and a click each on a sequence with no choices in it. 

223 

224 ``trailing`` (UX-113), when given, is called with a column beside the 

225 title — e.g. stage 2's "↩️ Restore a saved setup" popover trigger — so it 

226 reads as part of the title line instead of as the first thing in the body. 

227 Only the title line splits; the returned body container stays full width. 

228 

229 ``note`` (UX-135) hangs the part's explanation off the title as the same 

230 hover tooltip the rest of the wizard's prose uses, instead of a `st.caption` 

231 line under it. The add screen's own three titles say everything they need to 

232 ("Dataset name"), so only the ✏️ Edit dataset screen passes one — its parts 

233 carry judgements a title cannot ("does the Trial ID identify one reading?"). 

234 """ 

235 box = host.container(key=part_key(step.id)) 

236 mark = f"{badge(status)} " if status else "" 

237 title = html.escape(step.title) 

238 if note: 

239 title = ( 

240 f'<span class="sps-fhelp" data-tip="{html.escape(note, quote=True)}">' 

241 f"{title}</span>" 

242 ) 

243 title_html = ( 

244 f'<div class="sps-wiz-part"><span class="sps-wiz-part-n">{step.number}</span>' 

245 f"{mark}{title}</div>" 

246 ) 

247 if trailing is not None: 

248 title_col, trailing_col = box.columns( 

249 [0.6, 0.4], gap="small", vertical_alignment="center" 

250 ) 

251 title_col.markdown(title_html, unsafe_allow_html=True) 

252 trailing(trailing_col) 

253 else: 

254 box.markdown(title_html, unsafe_allow_html=True) 

255 return box.container()

263def first_incomplete(statuses: Mapping[str, StepStatus]) -> str | None: 

264 """Id of the first step that still wants attention, or ``None`` when the 

265 wizard is fully answered. 

266 

267 "Wants attention" excludes ``OPTIONAL``: an untouched optional step must not 

268 stop the accordion advancing past it, or *Extra fields* would grab focus 

269 ahead of *Name & add* on every fresh upload. 

270 """ 

271 for step in STEPS: 

272 status = statuses.get(step.id, StepStatus.TODO) 

273 if status in (StepStatus.TODO, StepStatus.ACTION): 

274 return step.id 

275 return None

278def go_to_step(step_id: str) -> None: 

279 """Open exactly one step and close the others. 

280 

281 Safe as an ``on_click``/``on_change`` callback: callbacks run as part of the 

282 click event, *before* the script re-executes, so these writes land before the 

283 expander widgets instantiate and Streamlit never sees a key being set for an 

284 already-created widget. 

285 """ 

286 for step in STEPS: 

287 st.session_state[open_key(step.id)] = step.id == step_id

290def seed_open_step(statuses: Mapping[str, StepStatus]) -> None: 

291 """On first entry to the wizard, open the first step that needs attention. 

292 

293 Runs once per wizard entry (guarded by ``_wizard_accordion_seeded``) — after 

294 that the accordion is the user's to drive, and re-seeding on later runs would 

295 be exactly the auto-advance-under-the-cursor behaviour this design removes. 

296 """ 

297 if st.session_state.get("_wizard_accordion_seeded"): 

298 return 

299 st.session_state["_wizard_accordion_seeded"] = True 

300 go_to_step(first_incomplete(statuses) or STEPS[0].id)

303def reset_accordion() -> None: 

304 """Forget the accordion state so the next wizard entry re-seeds. 

305 

306 Called by ``wizard._reset_wizard_widgets`` when *Add data* starts a fresh 

307 dataset; without it the second dataset would open on whichever step the 

308 first one was left on. 

309 """ 

310 st.session_state.pop("_wizard_accordion_seeded", None) 

311 for step in STEPS: 

312 st.session_state.pop(open_key(step.id), None)

315def step_panel(host, step: WizardStep, status: StepStatus, *, active: bool): 

316 """The container a step's body renders into. 

317 

318 ``active`` (the guided wizard) gives a keyed expander; ``on_change="rerun"`` 

319 is what makes Streamlit track its open state at all — with ``key=`` alone the 

320 frontend keeps one open state while session state keeps another, so the 

321 user's manual collapse is never recorded and the next rerun re-opens it. 

322 

323 ``active=False`` is the collapsed *Data & mapping* review panel, which is 

324 itself an expander: Streamlit forbids expander-in-expander, so the step 

325 degrades to a bold heading and renders inline into ``host``. That preserves 

326 today's review-panel behaviour and the ``wizard_reconfigure`` assertion in 

327 ``tests/test_apptest.py``. 

328 

329 ``status`` is deliberately **not** rendered into the active header. A keyed 

330 expander whose label or icon changes remounts collapsed on the next run, so a 

331 status badge there would slam the step shut the moment an upload or a mapping 

332 pick completed it — see the module docstring. The badges live on the progress 

333 chips directly above, which are buttons and re-render harmlessly. 

334 """ 

335 if not active: 

336 host.markdown(f"**{badge(status)} {step.number}. {step.title}**") 

337 return host 

338 return host.expander( 

339 f"{step.number}. {step.title}", 

340 key=open_key(step.id), 

341 on_change="rerun", 

342 )

345def blockers( 

346 statuses: Mapping[str, StepStatus], reasons: Mapping[str, Iterable[str]] 

347) -> list[tuple[WizardStep, list[str]]]: 

348 """Steps still blocking *Add dataset*, each with its reasons. 

349 

350 Feeds the review step's "what's left" list, where every entry gets a 

351 *Go to step N* button — a blocker the user cannot navigate to is just a 

352 complaint. 

353 """ 

354 out: list[tuple[WizardStep, list[str]]] = [] 

355 for step in STEPS: 

356 if statuses.get(step.id, StepStatus.TODO) in ( 

357 StepStatus.TODO, 

358 StepStatus.ACTION, 

359 ): 

360 out.append((step, list(reasons.get(step.id, [])))) 

361 return out
