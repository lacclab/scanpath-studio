How this tracker works

Every item has a stable ID you can cite in chat ("let's do CMP-3"), a status, and a short write-up with code anchors. The data lives in tracker/data.js — edit that file; this page just reads it.

Status

  • Backlog — captured, not scheduled, but eligible.
  • Planned — next-ish, scoped.
  • In progress · Blocked.
  • Parked — deliberately deferred; not to be picked up as ordinary next work. Park with a date and a one-line reason; unparking is just a status change.
  • Pending approval — implemented, awaiting the user's final sign-off.
  • Done / Dropped — set "archived": true at the same time.

Write-up shape

Four bold-led paragraphs, in this order, so the ask stays legible next to what shipped (there are no headings — the renderer is deliberately tiny):

  • Request — what was asked for, in the asker's terms.
  • What was done — what actually shipped.
  • What's left — what remains, or Nothing. Say it either way, and link the follow-up item when the remainder was split out.
  • Background (technical) — code anchors, design calls, gotchas, related IDs. The internal half, kept out of the first three.

A Backlog item has only Request (plus Background) — the other two appear once there is work behind it. An implemented item keeps its status line as the leading > quote.

Rules

  • Approval gate. When implementation is finished, mark it Pending approval — never jump straight to Done. Only after the user signs off does it become Done + archived: true. An item closed without being implemented is archived the same way, with the reason.
  • IDs are stable. Never renumber. New items take the next free number in their prefix (see below); archived items keep their ID.
  • Composite asks are split into sub-items so they can land independently.
  • When implementing an item, ask for clarification as needed before starting.
  • When any view, measure, severity, or path here lands, update AGENTS.md, scanpath_studio/CLAUDE.md, CHANGELOG.md and the docs/ site in the same change.

Adding an item

Append to items in tracker/data.js. body is an array of markdown lines (one entry per source line, so diffs stay line-by-line):

{
 "id": "VIZ-22",
 "prefix": "VIZ", "num": 22, "sub": "",
 "title": "Short imperative title",
 "status": "Backlog", "note": "", "date": "",
 "group": "Visualization & display", "subgroup": "",
 "archived": false,
 "body": ["First line of the write-up.", "Second line — **VIZ-4** cross-refs auto-link."]
}
