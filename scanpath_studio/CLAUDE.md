# scanpath_studio

Streamlit workbench for exploring eye-tracking-while-reading scanpaths: word boxes, fixations, saccades, density heatmaps, and per-word reading measures (FFD/FPRT/RPD/TFD, regressions). Top-level [README](../README.md) covers install/release.

## Run

```bash
streamlit run scanpath_studio/app.py        # dev
python -m scanpath_studio                    # packaged
scanpath-studio                                  # console entry point
scanpath-studio render --sample -o out.html      # headless single-trial render
```

The console script is `cli.main` (dispatch in `cli.py`): `run`/no-args/unknown
args launch the app via `streamlit run` (default port 8501, backward compatible
with bare streamlit flags); `render` builds one trial's figure headless through
`api.py`. `__main__.py` delegates to the CLI.

## Modules

- [app.py](app.py) — orchestrator: page config, sidebar render, data load + normalization (`prepare_data`/`_normalize_pair`), public-dataset loaders, filter, and `main()`. **Three concerns were split out for navigability** (app.py 4087→~1640 lines): deep links + plot-config save/restore + Share + the Corpus⇄Scanpath view toggle → [url_state.py](url_state.py); the Upload/Add-dataset wizard → [wizard.py](wizard.py); data-source + view-label constants → [constants.py](constants.py). The wizard reaches a few app-resident data-IO/normalize helpers (`_read_uploaded_frame`, `_normalize_pair`, `_stash_active_mapping`, `_render_unmapped_view`, `render_sidebar_canvas_controls`) via `app.<name>` at call time (keeps the `app._read_uploaded_frame` AppTest seam; avoids an app⇄wizard cycle). URL-preset parsing (`?source=onestop&participant=pid&trial=N&show_saccades=1`), **view dispatch** (two top-level views — `main_nav` (session state) is set by the header **Corpus Analysis ⇄ Scanpath** toggle button in `_render_about_panel`; `_active_view` normalizes it and `main` does `if/elif` over `render_single_trial_tab`/`render_corpus_analysis_tab`. **Data Inspection** + **Share** are now subtabs of the Scanpath view, not standalone views; the **About** popover lives in the sidebar Help group via `_render_about_sidebar`). The **Share** subtab (`_render_share_body`, passed into `render_single_trial_tab` as `share_renderer`) builds a deep link from the current state via `_build_share_query` (inverse of `_URL_PRESETS` + `_SHAREABLE_SOURCES`, reading `_share_selection` written by `tabs.render_single_trial_tab`); a same-origin `components.html` widget composes the full URL client-side and copies it. The link adds `?trial_id=<canonical id>`, applied **after** combos exist by `_apply_url_trial_selection` (reusing `_restore_selection`, once-guarded) so it lands on the exact trial in any picker mode — unlike `?trial=` (a slider index seeded pre-widget in `_apply_url_preset`). Data sources: bundled demo, synthetic, **Public datasets** (`PUBLIC_DATASET_REGISTRY`: label → `{loader, monitor size, short, language, size, description, link}`; picked via a **searchable selectbox** `_load_public_dataset` that displays the `short` name + a language·size caption / description / home link, scaling past a long radio as the catalogue grows. PoTeC via `_load_potec_source` → `datasets.potec_raw_frames` and MultiplEYE via `_load_multipleye_source` → `datasets.multipleye_raw_frames` (+ OneStop via `_load_onestop_public_source`), all cached. Each loader renders a **directory + Expected-files + access-status** UI via the shared `_dataset_dir_input` / `_dataset_access_status` helpers: an *Expected files* layout (`_POTEC_STRUCTURE_MD` / `_MULTIPLEYE_STRUCTURE_MD` / `_onestop_structure_md`) and a **found vs. ⬇ Download** status (a one-click button calling `datasets.download_potec` / `download_onestop`, gated on `datasets.potec_present` / `onestop_present` / `multipleye_inventory`) — replaced the always-on "Download if missing" checkbox. **No per-source participant/text narrowing anymore** — each loader reads the *whole* corpus (`potec_raw_frames(root)` etc.) and the global **Narrow by** trial filters scope it; the headless `load_potec`/`load_multipleye` keep their `readers`/`texts`/`sessions`/`stimuli` args. Add a corpus with one registry entry + one loader; **feature-flagged off** until a future release: shown only when `SCANPATH_PUBLIC_DATASETS=1` / `public_datasets_enabled()`), OneStop (`$ONESTOP_DATA_DIR`), upload (multi-file per table; either table optional), and **stored uploaded datasets** (each finished upload is persisted in `st.session_state["_datasets"][name]` as pre-normalized `{words,fixations,raw_gaze,filter_fields,composite_trial_columns}` and becomes a first-class switchable source — selecting it reloads instantly via the `elif data_choice in _datasets` branch in `main`, no re-upload). Its mapping is **editable post-normalization** from the Data Inspection **Column mapping** section (`tabs._render_remap_editor` → `data.remap_normalized_frame`): the editor offers only the columns that survived the first normalization (a note lists the `dropped_columns` recorded at finalize) and overwrites the entry in place; the `_datasets` branch re-publishes the re-derived frames + new schema verbatim. `prepare_data` returns `(words, fixations, problems)` and no longer `st.stop()`s on a bad mapping — when `problems` is non-empty `main` calls `_render_unmapped_view(...)` to show the raw uploaded tables while the sidebar Column-mapping panels stay editable, so the user can see the columns they need to map. The **Upload** source goes through the hybrid setup wizard `_render_data_setup` (a main-area guided flow on first load → a collapsed "Data & mapping" panel after; entered via the sidebar "➕ Add data" button). A **Dataset format** `st.segmented_control` (`wizard_dataset_format`, key set; Generic | MultiplEYE) sits under the dataset name; **MultiplEYE** branches to `_render_multipleye_upload` (two upload boxes `mpe_fix`/`mpe_aoi` → `datasets.multipleye_frames_from_uploads` → `_normalize_pair` → the same `_wizard_finalize_payload`/`_finalize_wizard_dataset` storage as a finished generic upload, with `composite_trial_columns=[]` + `filter_fields=[genre,session,is_practice]`), bypassing the generic mapping steps. The **Generic** flow keeps its granular ordered steps (upload+counts → optional **derive ids from filename** via `_wizard_filename_derive` (delimiter split → `file_part_N`, *or* regex named groups via `extract_columns_from_source_file`) → unified/per-table trial id → required fields incl. an optional **Aggregate character AOIs into word boxes** toggle (`wizard_aggregate_char_boxes`, applied at finalize via `data.aggregate_char_boxes`) → optional participant/text → keep-fields/filters → inline **Experimental Setup** → name & finish), reusing `column_mapping_ui`/`_read_uploaded_frame`. Frames are read via the `_read_uploaded_frame` seam (monkeypatched in AppTests since `st.file_uploader` can't be driven); normalization is shared with `prepare_data` via `_normalize_pair`.

- [api.py](api.py) — headless public API (re-exported lazily from the package root): `load_scanpath_data` (paths/frames → schema-infer → normalize, raises `ValueError` instead of `st.error`), `load_sample_data`, `list_trials`, `compute_word_metrics`, `plot_scanpath`/`animate_scanpath` (single-trial wrappers around the `plots` builders with the app's sidebar defaults baked into `CANONICAL_FIGURE_DEFAULTS`), `save_figure` (extension-dispatched HTML/PNG/SVG/PDF). Quiets streamlit's bare-mode cache warnings — import order in this file is load-bearing, see its header comment.
- [cli.py](cli.py) — console entry point: subcommand dispatch (`run`, `render`, `--version`, `--help`); unknown args forward to `streamlit run` for backward compatibility. `render` exposes the api.py pipeline with per-layer `--no-*` flags, `--animate` (HTML only), `--list-trials`.
- [data.py](data.py) — schema inference for EyeLink/Gazepoint/snake_case columns (`propose_*_schema`; candidate lists also cover MultiplEYE's `location_x/y`, `onset`, `top_left_x/y`, `word_idx/char_idx`), normalization, `load_onestop_server_bundle` (fast-path per-pid Parquet, falls back to full CSV.zip), `compute_word_metrics`. Flexible-dataset plumbing: `read_tables`/`expand_table_inputs` (concatenate a list/glob of files, tagging each row with `source_file` — **now including a single file**, so filename-keyed identity is always recoverable), filename-derivation helpers `split_source_file` (delimiter → `file_part_N`) and `extract_columns_from_source_file` (regex named groups → columns, robust to variable-length parts; optional lowercase) for ids that live only in the filename, `aggregate_char_boxes(df, word_schema)` (collapse one-row-per-character AOI tables to one bounding box per word, grouped by the mapped trial + word id — run pre-normalization), `empty_words_frame`/`empty_fixations_frame` (canonical typed empties for single-report datasets), and `harmonize_frames` = `broadcast_stimulus_words` (replicate participant-less word boxes across the readers in the fixations) + `fill_fixation_xy_from_words` (place coordinate-less AOI fixations at word-box centers). Word participant + fixation x/y are now optional in `validate_*_schema`. `remap_normalized_frame(frame, schema, *, kind)` re-derives an already-normalized frame under a new mapping (drops the precomputed `unique_*` ids so a changed Trial/Text pick wins, keeps every surviving column) — powers the Data Inspection post-normalization remap; `dropped_columns(raw, *, keep|schema)` reports which source columns were discarded (the remap note).
- [datasets.py](datasets.py) — ready-made loaders for public corpora: `load_potec` + `download_potec` (+ `potec_raw_frames`) and `load_multipleye` (+ `multipleye_raw_frames` / `multipleye_inventory`), both returning pre-normalization frames the app's data sources feed through their own auto-detect/column-mapping. PoTeC exercises the flexible pipeline end to end (900 per-trial fixation TSVs concatenated, stimulus-level word AoIs with no participant column, fixation x/y reconstructed from per-text character-AoI `.ias` box centers). MultiplEYE parses participant/session/trial/stimulus from the **folder + file names** (no identity columns): each reader is a *session* (`participant_id="001_ZH_CH_1_ET1"`; ET1/ET2 read disjoint stimuli), each stimulus *page* is its own trial (`trial_id="<stim>__page_0N"`, zero-padded so the picker sorts pages numerically; displayed as "<stim> · page N" via `utils._trial_display_label`, since pages reuse the same screen coords) with `text_id`=stimulus, char-level AOI files aggregated to one box per `(page, word_idx)`, and non-reading screens dropped. The image-relative coords are shifted by `_MULTIPLEYE_IMAGE_ORIGIN` (`(monitor−image)/2` = (305, 44.5)) onto where the **centered** stimulus appeared on the full screen, so `MULTIPLEYE_MONITOR=(1920,1080)` (the real monitor) renders true-to-scale; the image-placement origin is stamped as `image_x`/`image_y`. The stimulus typeface is read from the stimulus config (`stimuli_*/config/config_*.py` — `_multipleye_font_config` regex-extracts `FONT_SIZE` + `FONT`, never execs it) and stamped as `stimulus_font_px` / `stimulus_font_family` (a CSS stack via `_multipleye_font_css`, e.g. NotoSansMonoCJKsc → `'Noto Sans Mono CJK SC', …`) so the app can render the reading text at the exact size/typeface the images were drawn with; both columns are registered meta passthrough fields in `data.WORD_OPTIONAL_FIELDS`/`FIX_OPTIONAL_FIELDS` so they survive normalization. Both build the frames then route through `api.load_scanpath_data` with explicit schemas. **Side-data enrichment** (each gated on its file/dir existing): `participant_data.csv` merged by `int(participant)`+`session` → `pp_*` reader-metadata columns; `multipleye_comprehension_questions_*.xlsx` → a per-stimulus `comprehension_questions` JSON column; `reading_measures/` → canonical `IA_*` measures attached to **per-reader** word boxes (`_multipleye_words_per_reader`; when present the boxes carry `participant_id` → `MULTIPLEYE_WORD_SCHEMA_PER_READER` → no stimulus-broadcast); stimulus page-image path stamped per `(stimulus,page)` (`image_path`). For **browser upload** (folders stripped), `multipleye_frames_from_uploads(fix_df, aoi_df, *, questions_df, participant_meta_df)` / `load_multipleye_uploads` recover identity from each row's `source_file`, case-matching the lowercase AOI filenames to the CamelCase fixation stimuli, and merge questions/metadata when uploaded (RM + images need the directory tree). Shared cores `_multipleye_word_boxes_from_frame` / `_stamp_multipleye_fixations` back both paths. Re-exported lazily as `sps.load_potec` / `sps.load_multipleye`.
- [plots.py](plots.py) — Plotly figure builders: `make_scanpath_figure` (core layered: words + fixations + saccades + heatmap), `make_comparison_figure`, `make_scanpath_animation`, bar/histogram figs. Overlay layers are factored into per-layer helpers (`_add_saccade_layer`, `_add_raw_gaze_layer`, the `_add_*_heatmap` family); the true-to-scale/equal-aspect setup, the colorbar/legend margin tracking, and the fixation-colour core stay inline in `make_scanpath_figure` (the fragile parts — see the true-to-scale gotchas below). **True-to-scale text:** word labels are sized in *data* space (`_word_label_font_px`: `_line_pitch / line_spacing`, capped by box width via `_width_fit_font`) then converted to screen px with `_display_scale`, so the reading text always fills the real line slot instead of being a fixed font size. The budget is the **line pitch** (`_line_pitch` = median line-to-line gap via `measures.cluster_word_lines`), *not* the raw box height — OneStop boxes tile the lines (pitch == height, so unchanged) but corpora whose AOI boxes hug the glyph (MultiplEYE) need the taller pitch. `_width_fit_font` is script-aware: it sums per-character advances (full-width CJK ≈ 1 em via `_is_fullwidth`, half-width Latin = `_latin_advance` — 0.5 in a CJK font, 0.6 in a Latin one) so a CJK word boxed next to a half-width Latin URL isn't sized down to the narrow run. `line_spacing` (default 3 = OneStop's one-blank-line-above-and-below) and `scale_text_to_boxes` thread through every spatial builder. When a dataset ships its real typeface (MultiplEYE stamps `stimulus_font_px`/`stimulus_font_family`), `app.render_sidebar_canvas_controls` snaps the font controls to it (exact px + CJK family, scale-to-boxes off) on a source switch, so the labels match the stimulus exactly rather than relying on the geometry inference. **Stimulus-image background layer:** `make_scanpath_figure(background_image=<path>, background_image_size=(w,h), background_image_origin=(x0,y0))` adds a `layout.image` at data `(x0,y0)-(x0+w,y0+h)` (origin defaults to `(0,0)`; MultiplEYE passes the centered origin so the image aligns with the offset coords), `layer="below"`, `yanchor="top"` (reversed y) — the page render under the scanpath, exact coordinates (MultiplEYE; sidesteps CJK/RTL fonts). `_image_to_data_uri` base64-encodes the path inside the builder (small cache key); `_png_pixel_size` reads dims from the PNG header. Only on `make_scanpath_figure` (not the animation/comparison builders); toggled via `controls.global_show_stimulus_image`, threaded by `tabs.render_single_trial_tab`. **PRE-3 drift connectors:** `make_scanpath_figure(show_connectors=True, connector_y=<orig y per fixation>)` adds ONE faint grey Scatter (vertical segment from each fixation's original y to its already-snapped y) before the fixation markers — the corrected fixations come in pre-snapped via `alignment.correct`, so no new colour path (reuses `color_by_line`).
- [measures.py](measures.py) — `assign_fixations_to_words` (bbox containment + nearest-word within 50 px), then per-word FFD/FPRT/RPD/TFD/skip/regression. Used only when pre-aggregated columns (e.g. `IA_FIRST_FIXATION_DURATION`) are absent. Also geometry helpers `cluster_word_lines`, `fixation_in_text_mask`, `assign_fixation_lines` powering the out-of-text + color-by-line plot options.
- [alignment.py](alignment.py) — **PRE-3** vertical drift-correction: a native port (CC BY 4.0, see [`NOTICE`](../NOTICE)) of the ten Carr et al. (2021) line-assignment algorithms (`ALGORITHMS` = attach/chain/cluster/compare/merge/regress/segment/split/stretch/warp; no `slice`). Pure NumPy + `scipy` (k-means for cluster/split, `minimize` for regress/stretch, DTW for warp/compare). Core `assign_lines(fixation_XY, line_Y, *, word_XY, method) → int line indices`; DataFrame wrapper `correct(fixations, words, method, *, snap=True) → (corrected_fixations, assigned_line)` snaps `y` to the assigned line center (float-cast first so an int `y` column doesn't raise) and returns a float line Series with the **same semantics as `measures.assign_fixation_lines`** (so the `color_by_line` plot path consumes it unchanged). Line centers via `measures.cluster_word_lines`; reading-order word centers (warp/compare) via `model_scanpaths._ordered_word_rows`. Passthrough when <2 lines / empty; NaN-coord fixations dropped from the algorithm and left unassigned.

- [animation_export.py](animation_export.py) — rasterize the animated-scanpath `go.Figure` to GIF/MP4 (`export_animation`). Uniform per-frame duration matches the on-screen Play, so clip runtime == quoted playback time.

Two styles via `TOUR_STYLE`: **spotlight** (default) — a fixed-position keyed-container card (`render_spotlight_tour`, called early in `main()` right after `maybe_show_welcome_tour` so the card streams before the heavy data/plot work; the replay button arms it via an `on_click` callback, which runs before the rerun) plus a per-step pulsing CSS outline on `.st-key-tour_grp_*` wrapper containers around the sidebar sections (app.py/controls.py/annotations.py — keep `_SPOTLIGHT_STEPS` selectors in sync), with a same-origin iframe script scrolling the target's own scroll container into view (first *visible* match only — inactive tab panels hold invisible duplicates); and **dialog** — a 6-step `st.dialog`. - [utils.py](utils.py) — trial selection UI. ## Data flow

1. Load: upload (one or many files per table; either table may be omitted), bundled `sample_data/`, the synthetic test trial, OneStop server bundle (`$ONESTOP_DATA_DIR` set), or a `datasets.py` corpus loader (PoTeC).
2. Infer schema → normalize column names to canonical form.
3. Compute reading measures if pre-aggregated columns missing.
4. Filter by participant/trial/text (sidebar).
5. Dispatch to one of two views via the header **Corpus Analysis ⇄ Scanpath** toggle button (key `main_nav`): Scanpath Visualization, Corpus Analysis. Data Inspection + Share are subtabs of the Scanpath view (not standalone views).
6. Bulk export is the **Export** subtab of the Scanpath view (`tabs._render_export_panel`), no longer a separate step.

## OneStop integration

`onestop_shard.py` solves cold-start: full CSV load takes ~3 min, per-pid Parquet shard loads in ~1 sec. When `$ONESTOP_DATA_DIR` is set AND `?participant=<pid>` is in URL, `load_onestop_server_bundle` reads only that pid's shard. Without a pid, it falls back to the full CSV.zip. An external review app embeds this app via iframe with deep-link URL params.

## Gotchas

- **Code changes not showing? Restart the server.** Streamlit doesn't reload imported modules on rerun, and `st.cache_data` doesn't hash transitively-called helpers — so after editing a module (or a helper a cached loader calls), a rerun / "Clear cache" isn't enough; kill and restart the process (it may run as `python -m scanpath_studio`). See CONTRIBUTING → "If a code change doesn't show up".
- URL deep-link presets are applied before widgets render (in `app.py`); changing widget keys breaks deep-links.
- Schema auto-detection (`data.pick_column`) matches candidate names case- and separator-insensitively (`IA_LEFT`==`ia_left`==`Ia-Left`, `Participant ID`==`participant_id`), so the `*_CANDIDATES` lists hold only distinct conventions, not case variants. Candidate order is still priority order, so EyeLink names beat Gazepoint when both match — override via sidebar `column_mapping_ui` if needed.
- Word-box mapping (`controls.WORD_FIELD_SPECS` `kind:"box"`) renders one coordinate-format radio (edges `left/right/top/bottom` ↔ origin+size `x/y/width/height`) + 4 fields instead of 8, but `column_mapping_ui` still returns all 8 box keys (inactive 4 = None) so `data.normalize_words`/`validate_word_schema` and the headless API keep their fixed schema-dict shape. `*` on a mapping field now means exactly "validation blocks without it" (so Participant ID is *not* starred — stimulus-level word tables omit it; the box group *is*). For Fixations, X/Y are likewise unstarred — conditional on a location being present (X/Y **or** a Word/IA ID, which is also the authoritative word assignment when given); only Participant/Trial/Duration are required. `saccade_amplitude` is now a mappable field (proposed + normalized) and falls back to the X/Y-computed value.
- Pre-aggregated reading-measure columns (EyeLink IA_* columns) win over computed `measures.py` outputs; the recomputation is a fallback, not the primary path.
- When the source data lacks a `unique_trial_id` column (e.g. OneStop L2 shards), `normalize_*` falls back to `unique_paragraph_id` and disambiguates repeated readings by ranking on `TRIAL_INDEX` — the 2nd reading gets a `_r2` suffix on `trial_id`. Without this, both readings of a repeated-reading trial collapse into one scanpath. Alternatively, the Trial ID column mapping is a **multiselect**: a multi-column choice builds a composite `unique_trial_id` on the fly (`data.trial_id_series`, values joined with `_`) and is authoritative — it overrides a raw `unique_trial_id` column and skips the `_r2` disambiguation. The composite's component columns are preserved into the normalized frames (`data._preserve_composite_columns`) and flagged via `st.session_state["_composite_trial_columns"]` (set wherever frames are normalized — `app._normalize_pair`, `prepare_data`, and the upload wizard `_render_data_setup`; for a stored uploaded dataset it's persisted in the `_datasets` entry and re-published when the dataset is reselected), so *Select trials by → Trial* renders one cascading selector per component (`utils._select_trial_composite_mode`) instead of a single opaque dropdown.
- `st.select_slider` must never be given a single option — the Python side accepts it but the browser slider throws `RangeError: min (0) is equal/bigger than max (0)` and blanks the tab (invisible to AppTest, which runs no frontend). The Participant-mode trial picker (`utils._select_trial_participant_mode`) renders the lone value as a caption instead; guard any new slider the same way (cf. the `max_fix >= 2` guard in tabs.py).
- Bulk export iterates *all* filtered trials — narrow the filter before clicking export on the full OneStop set.
- Static image export (PNG/SVG/PDF) **and the animation GIF/MP4 export** go through Kaleido v1, which needs a Chrome/Chromium binary. Locally run `plotly_get_chrome -y` once; on Streamlit Cloud it's installed via the repo-root `packages.txt` (`chromium`). The **HTML** save format is a browser-free fallback (`fig.to_html`) when no Chrome is available — for the animation tab, HTML is also the only browser-free export (GIF/MP4 raise `AnimationExportError`, surfaced as a warning pointing back to HTML). MP4 needs no system ffmpeg: the `imageio[ffmpeg]` extra bundles the binary.
- The bundled `raw_gaze.{csv,parquet}` is **synthesized** from one real bundled trial's fixations (`update_sample_data.synthesize_raw_gaze`) — OneStop ships no sample-level gaze. It must stay keyed to a (participant, trial) present in the bundled fixations or the app filters it to 0 rows (regression-guarded in `tests/test_raw_gaze_sample.py`). Regenerate with `python -m scanpath_studio.update_sample_data --raw-gaze-only`.
- AOIs are taken from the data's word boxes, not computed. Only fixation→word assignment is derived (`measures.assign_fixations_to_words`); "out-of-text" = a fixation inside no box; "by-line" infers lines from word-box `y` because `line_idx` is usually constant.
- **Don't render the spatial plots with `st.plotly_chart`.** Streamlit pins the chart *width* to the column while keeping the layout *height*, which re-lays-out Plotly to an unknown scale and leaves the px-sized word labels mismatched to the boxes (the true-to-scale text breaks). The single/animation/comparison plots go through `tabs._render_true_scale_chart`, which embeds the figure's own HTML at its exact pixel size and CSS-scales the whole block uniformly to the column width. Figure size is capped (`plots._DISPLAY_MAX_*`) so it fits a research display; PNG export bumps `scale` to stay crisp (SVG/PDF are vector). The embed loads plotly from CDN (needs network) and re-mounts each rerun.
- **Animation transport controls must not shrink the plot.** The animation figure has `scaleanchor="x", scaleratio=1`, so if Plotly's automargin reserves vertical space for the play/pause/restart buttons + time slider, the *whole* equal-aspect plot shrinks — and the word boxes then render smaller than the true-to-scale label font computed for `fitted_h`, so the text looks oversized (the "animation text too large" bug). Fix: all transport controls sit BELOW the plot in the bottom margin, and the figure is grown by `plots._CONTROLS_MARGIN_PX (+ _CONTROLS_SAFETY_PX)` so the plot region stays ≥ `fitted_h` (width-bound) — i.e. the same box size as the static `make_scanpath_figure`. If you move/resize those controls, re-check the box height matches the static plot (~0.28 font-to-box ratio on the demo).
- Annotations (favorites/tags/notes) live in `st.session_state` only — persistence is via the sidebar JSON download/restore. They don't survive a hard refresh unless re-imported, and on the shared cloud demo they're per-session. Annotation-based trial filters reflect a star/tag on the *next* rerun (the editor writes the store after the sidebar filter reads it).
