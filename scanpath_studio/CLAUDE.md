# scanpath_studio

Streamlit workbench for exploring eye-tracking-while-reading scanpaths: word boxes, fixations, saccades, density heatmaps, and per-word reading measures (FFD/FPRT/RPD/TFD, regressions). Top-level [README](../README.md) covers install/release.

## Run

```bash
streamlit run streamlit_app.py               # dev (root shim → scanpath_studio.app.main)
python -m scanpath_studio                    # packaged
scanpath-studio                                  # console entry point
scanpath-studio render --sample -o out.html      # headless single-trial render
```

The console script is `cli.main` (dispatch in `cli.py`): `run`/no-args/unknown
args launch the app via `streamlit run` (default port 8501, backward compatible
with bare streamlit flags); `render` builds one trial's figure headless through
`api.py`. `__main__.py` delegates to the CLI.

## Modules

**ENG-28 ownership rule:** renderers receive one `plots.FigureSettings` value;
the UI, headless API, and bulk export must build that contract instead of growing
parallel argument lists. Public-corpus discovery and server bundles belong to
`datasets.py` (never `data.py`), while fixation-run materialization belongs to
`measures.py` (and is re-exported by `preprocessing.py`). These directions keep
the core data dependencies acyclic.

The wizard reaches a few app-resident data-IO/normalize helpers (`_read_uploaded_frame`, `_normalize_pair`, `_stash_active_mapping`, `_render_unmapped_view`, `render_sidebar_canvas_controls`) via `app.<name>` at call time (keeps the `app._read_uploaded_frame` AppTest seam; avoids an app⇄wizard cycle). Data sources: bundled demo, synthetic, **Public datasets** (`PUBLIC_DATASET_REGISTRY`: label → `{loader, monitor size, short, language, size, description, link}`; picked via a **searchable selectbox** `_load_public_dataset` that displays the `short` name + a language·size caption / description / home link, scaling past a long radio as the catalogue grows. Add a corpus with one registry entry + one loader; shown by default — `public_datasets_enabled()` hides the group only when `SCANPATH_PUBLIC_DATASETS` is `0`/`false`/`no`. **DATA-27** made the registry a function: `public_dataset_registry()` = the static dict ∪ one entry per **prepared benchmark corpus** discovered in the local bundle (`discovered_benchmark_datasets()` → `_cached_eyegenbench_datasets`, keyed on `eyegenbench_dir`), because those depend on a directory the user can change at runtime. **Read the function, never the dict** — the dict answers for the three built-ins only. PoTeC and OneStop ship both natively and harmonised — both are kept, the harmonised copy shown as `"<Corpus> (harmonised benchmark)"` (`_benchmark_short_name`, computed against the built-ins' `short` names so a future overlap disambiguates itself). An entry omits `monitor` when the manifest's `monitor_source` is `default` (an invented screen must not snap the canvas) — the condition is `eyegenbench.declared_monitor(entry)`, read by `cli render --eyegenbench` too, so one corpus can't render at the invented screen on one surface and at data extents on the other; and `geometry_badge(entry)` says "measured word boxes for N of M texts" whenever `paragraphs_without_real_boxes > 0` — the scalar `geometry_source` is the *best tier any paragraph reached*, so a plain "Real" badge would overclaim uniformity. With **zero** corpora discovered the registry instead offers exactly one `BENCHMARK_SETUP_CHOICE` placeholder carrying the directory input, or a bundle at a non-default path would be unreachable — no entry, nowhere to type the path. That entry only *works* because of two things it is easy to undo: `_dataset_dir_input` passes `persist_state="session"` (this input renders only while its own corpus is selected, and the placeholder vanishes the moment the path it was given succeeds — an ordinary widget key would be dropped at end of that very run), and the picker's healing step sends a stale benchmark selection — the placeholder, or a corpus label whose corpus the current bundle no longer holds — to the first discovered corpus instead of `entries[0]`, so neither succeeding nor repointing the directory bounces the user to the demo), OneStop (`$ONESTOP_DATA_DIR`), upload (multi-file per table; either table optional), and **stored uploaded datasets** (each finished upload is persisted in `st.session_state["_datasets"][name]` as pre-normalized `{words,fixations,raw_gaze,filter_fields,composite_trial_columns}` and becomes a first-class switchable source — selecting it reloads instantly via the `elif data_choice in _datasets` branch in `main`, no re-upload). Its mapping is **editable post-normalization** from the Data Inspection **Column mapping** section (`tabs._render_remap_editor` → `data.remap_normalized_frame`): the editor offers only the columns that survived the first normalization (a note lists the `dropped_columns` recorded at finalize) and overwrites the entry in place; the `_datasets` branch re-publishes the re-derived frames + new schema verbatim. `prepare_data` returns `(words, fixations, problems)` and no longer `st.stop()`s on a bad mapping — when `problems` is non-empty `main` calls `_render_unmapped_view(...)` to show the raw uploaded tables while the ⚙️ Configure Column-mapping panels stay editable, so the user can see the columns they need to map. The **Upload** source goes through the hybrid setup wizard `_render_data_setup` (a main-area guided flow on first load → a collapsed "Data & mapping" panel after; entered via the "➕ Add data" button beside the source picker). A **Dataset format** `st.segmented_control` (`wizard_dataset_format`, key set; Generic | MultiplEYE) sits under the dataset name; **MultiplEYE** branches to `_render_multipleye_upload` (two upload boxes `mpe_fix`/`mpe_aoi` → `datasets.multipleye_frames_from_uploads` → `_normalize_pair` → the same `_wizard_finalize_payload`/`_finalize_wizard_dataset` storage as a finished generic upload, with `composite_trial_columns=[]` + `filter_fields=[genre,session,is_practice]`), bypassing the generic mapping steps. The **Generic** flow keeps its granular ordered steps (upload+counts → optional **derive ids from filename** via `_wizard_filename_derive` (delimiter split → `file_part_N`, *or* regex named groups via `extract_columns_from_source_file`) → unified/per-table trial id → required fields incl. an optional **Aggregate character AOIs into word boxes** toggle (`wizard_aggregate_char_boxes`, applied at finalize via `data.aggregate_char_boxes`) → optional participant/text → keep-fields/filters → inline **Experimental Setup** → name & finish), reusing `column_mapping_ui`/`_read_uploaded_frame`. Frames are read via the `_read_uploaded_frame` seam (monkeypatched in AppTests since `st.file_uploader` can't be driven); normalization is shared with `prepare_data` via `_normalize_pair`.

- [menu.py](menu.py) — **UX-38**: the app's chrome, after the sidebar was removed. `render_top_menu` draws one horizontal row of popovers — one per former sidebar group (⚙️ Configure · 🧹 Preprocessing · 💾 Save & restore · 🗄️ Recovery cache · ❓ Help, plus 🐛 Debug under `?debug=1`) — and returns them as a `TopMenu` of empty slots `app.main` fills by `host=`, the same reserve-then-fill discipline the sidebar containers had. **Popovers, not `st.dialog`**, and that is load-bearing: a dialog body only runs while it is open, but ⚙️ Configure's directory input, ⬇ Download button and column-mapping selectboxes *drive* `prepare_data` on every rerun, and Streamlit drops the state of a widget that doesn't render. A popover is a plain `DeltaGenerator` — executes every run, fillable long after later elements were written — i.e. exactly `st.sidebar`'s semantics. Consequence for panel authors: a popover nests neither an expander nor another popover, so a group that used to be `st.sidebar.expander("<title>")` renders **bare** into its slot (the trigger is the disclosure), and the two former popovers inside Help became dialogs (`tour._tutorial_library_dialog`, `app._about_dialog`) — each calling `close_open_popovers()` first, since a popover's open state is client-side and it would otherwise float over the modal it just opened. `render_nav` draws **Streamlit's own** `st.navigation(position="top")` and returns the active view; `.run()` is deliberately never called (the page bodies close over frames `main`'s long prelude computes, and the epilogue must run *after* the body), so `main` keeps its `if/elif` dispatch and the `st.Page` bodies never execute. **`main_nav` is a mirror, not the source of truth** — the router owns the selection, but `_go_corpus`/`_go_scanpath`/`tour`/`persistence` all still *write* `main_nav` to request a view, including from `on_click` callbacks where `st.switch_page` is illegal. `render_nav` reconciles against `_nav_mirrored` (what it wrote last run), which is what separates "the user clicked the nav" from "code asked to go back"; comparing `main_nav` to the selection directly makes a nav click read as a request to return, and the nav bounces (`tests/test_apptest.py::test_nav_click_is_not_bounced_back_by_the_reconciler`). `render_top_menu` must be called AFTER `restore_local_state` (or the router's default pins the view before the cache can restore it) and BEFORE any data loading (or the loaders have no slots to fill).
- [wizard_shell.py](wizard_shell.py) — **DATA-22**: the Add-dataset wizard's *chrome* — the seven-step registry (`STEPS`: data · identity · geometry · setup · **readers** · fields · review — DATA-20 added *About your readers*, which renders `tabs.render_participant_metadata_section(host=…)` and is the participant table's main home), `StepStatus`/badges, the keyed-expander accordion (`step_panel`), progress + clickable chips (`render_progress`), and navigation (`seed_open_step` / `go_to_step` / `continue_button` / `blockers`). Knows nothing about columns or frames. **The one rule:** a step's `wiz_open_<id>` flag is written ONLY by those shell functions and the guide — nothing inside a step body may touch it, which is what stops a step collapsing in response to its own edit (the DATA-19 bug, whose one-shot marker this replaced). Second rule: **never gate a step body on its expander being open** — Streamlit drops a not-rendered widget's key at end of run and `column_mapping_ui` builds `col_map_*` without `persist_state`, so a collapsed-and-unrendered step would silently discard its mapping; collapsed-but-rendered is correct. `wiz_open_*` is deliberately clear of the `col_map_*` prefix that `tabs._collect_column_mapping` sweeps into the saved config. Testing gotcha: `AppTest` never echoes an expander's open state back (a programmatic `True` reverts on the next *bare* rerun), so the accordion's survives-an-edit behaviour is browser-verified, not AppTest-verified.

- [data.py](data.py) — schema inference for EyeLink/Gazepoint/snake_case columns (`propose_*_schema`; candidate lists also cover MultiplEYE's `location_x/y`, `onset`, `top_left_x/y`, `word_idx/char_idx`), normalization, `load_onestop_server_bundle` (fast-path per-pid Parquet, falls back to full CSV.zip), `compute_word_metrics`. Flexible-dataset plumbing: `read_tables`/`expand_table_inputs` (concatenate a list/glob of files, tagging each row with `source_file` — **now including a single file**, so filename-keyed identity is always recoverable), filename-derivation helpers `split_source_file` (delimiter → `file_part_N`) and `extract_columns_from_source_file` (regex named groups → columns, robust to variable-length parts; optional lowercase) for ids that live only in the filename, `aggregate_char_boxes(df, word_schema)` (collapse one-row-per-character AOI tables to one bounding box per word, grouped by the mapped trial + word id — run pre-normalization), `empty_words_frame`/`empty_fixations_frame` (canonical typed empties for single-report datasets), and `harmonize_frames` = `broadcast_stimulus_words` (replicate participant-less word boxes across the readers in the fixations) + `fill_fixation_xy_from_words` (place coordinate-less AOI fixations at word-box centers). Word participant + fixation x/y are now optional in `validate_*_schema`. `remap_normalized_frame(frame, schema, *, kind)` re-derives an already-normalized frame under a new mapping (drops the precomputed `unique_*` ids so a changed Trial/Text pick wins, keeps every surviving column) — powers the Data Inspection post-normalization remap; `dropped_columns(raw, *, keep|schema)` reports which source columns were discarded (the remap note). **BUG-8:** `harmonize_frames` also runs `correct_word_id_offset` — `detect_word_id_offset` spots a fixation `word_id` numbered from 1 against 0-based word boxes (the bundled OneStop demo's shape, where every fixation pointed at the *next* word) and shifts it down by one. Detection is deliberately strict (whole-number ids both sides; words start at 0 and fixations at 1 *globally*; every shared trial 0-based + gap-free; at least one trial overflowing by exactly one) so a correct dataset is never touched, and the shift is logged at WARNING via the module logger rather than `st.warning` — the demo trips it on every load and a permanent banner on the landing view would be noise. **BUG-12:** `filter_to_keys` now delegates to a single-frame sibling `filter_frame_to_keys` (+ `trial_keys`), which is what routes the annotation (favorites/tags) filter through to **raw gaze** as well as words + fixations — without it a raw-gaze row for an unstarred trial survived and `app.main`'s all-three-empty guard (and the UX-7 panel behind it) never fired. **DATA-16/S6:** `_read_zipped_table` bounds decompression via `_check_zip_limits` (declared `ZipInfo.file_size` vs. `ZIP_MAX_MEMBER_UNCOMPRESSED_BYTES` / `ZIP_MAX_TOTAL_UNCOMPRESSED_BYTES` / `ZIP_MAX_COMPRESSION_RATIO`) *and* reads each member under a running byte budget, since the declared sizes are attacker-controlled. **PERF-3:** `frame_fingerprint` memoizes per run — a `threading.local` `OrderedDict` of `id(frame) → (weakref, fingerprint)`, LRU-evicted at `_FINGERPRINT_MEMO_MAX`, cleared by `reset_fingerprint_memo()` at the top of `app.main`. The weak ref is what makes the `id()` key safe (a collected frame's id may be reissued, but its ref is dead, so the lookup misses) *and* keeps the memo from pinning corpus frames for a session's idle time. It assumes no fingerprinted frame is mutated **in place** mid-run — true by construction today, documented at the call site, and the within-run form of audit finding S5.
- [datasets.py](datasets.py) — ready-made loaders for public corpora: `load_potec` + `download_potec` (+ `potec_raw_frames`) and `load_multipleye` (+ `multipleye_raw_frames` / `multipleye_inventory`), both returning pre-normalization frames the app's data sources feed through their own auto-detect/column-mapping. PoTeC exercises the flexible pipeline end to end (900 per-trial fixation TSVs concatenated, stimulus-level word AoIs with no participant column, fixation x/y reconstructed from per-text character-AoI `.ias` box centers). MultiplEYE parses participant/session/trial/stimulus from the **folder + file names** (no identity columns): each reader is a *session* (`participant_id="001_ZH_CH_1_ET1"`; ET1/ET2 read disjoint stimuli), and **DATA-24** makes one *reading of a stimulus* one trial (`trial_id == text_id == "<stim>"`) whose **screens** are the corpus's own `page` values — reading pages `page_1…page_N` **and** the comprehension-question screens `question_<id>` — each in its own coordinate space (`multipart.py`; both schemas map `screen_id="page"`). Three things there are easy to get silently wrong: (1) **`screen_index` is ranked from the reader's own fixation onsets** (`_multipleye_screen_order`), never from the screen name — pages are shown in page order but the *question order is shuffled per reader*; (2) **question-AOI rows join on `int(question_id)`** — the AOI file zero-pads the stimulus id (`question_04111`) and the fixations do not (`question_4111`), so a string match finds nothing; (3) the per-reader word frame is **inner-joined to the screens that reader actually fixated**, and any fixation on a screen with no boxes is dropped (`_multipleye_drop_screens_without_boxes`, logged) — otherwise `multipart.validate_matching_parts` rejects the orphan and kills the whole load. Question screens always come from `fixations/` whatever `fixation_source` says (the `scanpaths/` export is pre-filtered to reading pages), so a trial mixes provenance — visible as `screen_kind` (`reading`/`question`, a passthrough field in `data.WORD_OPTIONAL_FIELDS`/`FIX_OPTIONAL_FIELDS`). Which *answer layout* a reader saw comes from `stimuli_*/config/stimulus_order_versions_*.csv` keyed on the **bare pid** (`_multipleye_layout_versions`), and selects both the `<stim>_aoi_questions.csv` rows and the question image; inside a question screen the five blocks (stem/target/3 distractors) each restart `word_idx` at 0, so `_multipleye_question_screen_boxes` orders the blocks by their first character's geometry and runs one counter across them (`aoi_block` keeps the block name). Question screens are **on by default** — `include_question_screens=False` opts out (a loader kwarg, deliberately no CLI flag: `render` takes frames, not a corpus root, like the sibling `sessions`/`stimuli`/`fixation_source`). Reading-page char AOIs are aggregated to one box per `(page, word_idx)`; the rating/difficulty screens stay out (no AOI file ⇒ word-box-less screens, which multipart rejects by design). The image-relative coords are shifted by `_MULTIPLEYE_IMAGE_ORIGIN` (`(monitor−image)/2` = (305, 44.5)) onto where the **centered** stimulus appeared on the full screen, so `MULTIPLEYE_MONITOR=(1920,1080)` (the real monitor) renders true-to-scale; the image-placement origin is stamped as `image_x`/`image_y`. The stimulus typeface is read from the stimulus config (`stimuli_*/config/config_*.py` — `_multipleye_font_config` regex-extracts `FONT_SIZE` + `FONT`, never execs it) and stamped as `stimulus_font_px` / `stimulus_font_family` (a CSS stack via `_multipleye_font_css`, e.g. NotoSansMonoCJKsc → `'Noto Sans Mono CJK SC', …`) so the app can render the reading text at the exact size/typeface the images were drawn with; both columns are registered meta passthrough fields in `data.WORD_OPTIONAL_FIELDS`/`FIX_OPTIONAL_FIELDS` so they survive normalization. ## Data flow

1. Load: upload (one or many files per table; either table may be omitted), bundled `sample_data/`, the synthetic test trial, OneStop server bundle (`$ONESTOP_DATA_DIR` set), a stored uploaded dataset (`st.session_state["_datasets"]`), or a `datasets.py` corpus loader (PoTeC, MultiplEYE, OneStop public).
2. Infer schema → normalize column names to canonical form.
3. Compute reading measures if pre-aggregated columns missing.
4. Narrow the trial pool: inline **Narrow by** Text/Participant multiselects + the **More** condition/annotation filters (`controls.render_narrow_by` / `render_trial_filters`).
5. Dispatch to one of two views via Streamlit's native top nav (`menu.render_nav` → `st.navigation(position="top")`, mirrored into `main_nav`): Scanpath Visualization, Corpus Analysis. Data Inspection + Share are subtabs of the Scanpath view (not standalone views).
6. Bulk export is the **Export** subtab of the Scanpath view (`tabs._render_export_panel`), no longer a separate step.

## OneStop integration

`onestop_shard.py` solves cold-start: full CSV load takes ~3 min, per-pid Parquet shard loads in ~1 sec. When `$ONESTOP_DATA_DIR` is set AND `?participant=<pid>` is in URL, `load_onestop_server_bundle` reads only that pid's shard. Without a pid, it falls back to the full CSV.zip. An external review app embeds this app via iframe with deep-link URL params.

## Gotchas

- **Code changes not showing? Restart the server.** Streamlit doesn't reload imported modules on rerun, and `st.cache_data` doesn't hash transitively-called helpers — so after editing a module (or a helper a cached loader calls), a rerun / "Clear cache" isn't enough; kill and restart the process (it may run as `python -m scanpath_studio`). See CONTRIBUTING → "If a code change doesn't show up".
- URL deep-link presets are applied before widgets render (in `app.py`); changing widget keys breaks deep-links.
- Schema auto-detection (`data.pick_column`) matches candidate names case- and separator-insensitively (`IA_LEFT`==`ia_left`==`Ia-Left`, `Participant ID`==`participant_id`), so the `*_CANDIDATES` lists hold only distinct conventions, not case variants. Candidate order is still priority order, so EyeLink names beat Gazepoint when both match — override via the ⚙️ Configure `column_mapping_ui` if needed.
- Word-box mapping (`controls.WORD_FIELD_SPECS` `kind:"box"`) renders one coordinate-format radio (edges `left/right/top/bottom` ↔ origin+size `x/y/width/height`) + 4 fields instead of 8, but `column_mapping_ui` still returns all 8 box keys (inactive 4 = None) so `data.normalize_words`/`validate_word_schema` and the headless API keep their fixed schema-dict shape. `*` on a mapping field now means exactly "validation blocks without it" (so Participant ID is *not* starred — stimulus-level word tables omit it; the box group *is*). For Fixations, X/Y are likewise unstarred — conditional on a location being present (X/Y **or** a Word/IA ID, which is also the authoritative word assignment when given); only Participant/Trial/Duration are required. `saccade_amplitude` is now a mappable field (proposed + normalized) and falls back to the X/Y-computed value.
- Pre-aggregated reading-measure columns (EyeLink IA_* columns) win over computed `measures.py` outputs; the recomputation is a fallback, not the primary path.
- When the source data lacks a `unique_trial_id` column (e.g. OneStop L2 shards), `normalize_*` falls back to `unique_paragraph_id` and disambiguates repeated readings by ranking on `TRIAL_INDEX` — the 2nd reading gets a `_r2` suffix on `trial_id`. Without this, both readings of a repeated-reading trial collapse into one scanpath. Alternatively, the Trial ID column mapping is a **multiselect**: a multi-column choice builds a composite `unique_trial_id` on the fly (`data.trial_id_series`, values joined with `_`) and is authoritative — it overrides a raw `unique_trial_id` column and skips the `_r2` disambiguation. The composite's component columns are preserved into the normalized frames (`data._preserve_composite_columns`) and flagged via `st.session_state["_composite_trial_columns"]` (set wherever frames are normalized — `app._normalize_pair`, `prepare_data`, and the upload wizard `_render_data_setup`; for a stored uploaded dataset it's persisted in the `_datasets` entry and re-published when the dataset is reselected). The flag no longer shapes the **picker** in any way (BUG-23 — trial selection is always the standard selectbox + slider + ◀ ▶ arrows, whatever the mapping); its only consumers now are the trial chips, which spell the joined id back out part by part (`tabs._render_trial_condition_chips`), and the `build_combo_options` cache key, which has to carry the columns those chips read.
- `st.select_slider` must never be given a single option — the Python side accepts it but the browser slider throws `RangeError: min (0) is equal/bigger than max (0)` and blanks the tab (invisible to AppTest, which runs no frontend). The trial picker (`utils._select_trial_none_mode`) degrades a single-trial pool to just the selectbox instead; guard any new slider the same way (cf. the `max_fix >= 2` guard in tabs.py).
- Bulk export iterates *all* filtered trials — narrow the filter before clicking export on the full OneStop set.
- Static image export (PNG/SVG/PDF) **and the animation GIF/MP4 export** go through Kaleido v1, which needs a Chrome/Chromium binary. Locally run `plotly_get_chrome -y` once; on Streamlit Cloud it's installed via the repo-root `packages.txt` (`chromium`). The **HTML** save format is a browser-free fallback (`fig.to_html`) when no Chrome is available — for the animation tab, HTML is also the only browser-free export (GIF/MP4 raise `AnimationExportError`, surfaced as a warning pointing back to HTML). MP4 needs no system ffmpeg: the `imageio[ffmpeg]` extra bundles the binary.
- The bundled `raw_gaze.{csv,parquet}` is **synthesized** from one real bundled trial's fixations (`update_sample_data.synthesize_raw_gaze`) — OneStop ships no sample-level gaze. It must stay keyed to a (participant, trial) present in the bundled fixations or the app filters it to 0 rows (regression-guarded in `tests/test_raw_gaze_sample.py`). Regenerate with `python -m scanpath_studio.update_sample_data --raw-gaze-only`.
- AOIs are taken from the data's word boxes, not computed. Only fixation→word assignment is derived (`measures.assign_fixations_to_words`); "out-of-text" = a fixation inside no box; "by-line" infers lines from word-box `y` because `line_idx` is usually constant.
- **Don't render the spatial plots with `st.plotly_chart`.** Streamlit pins the chart *width* to the column while keeping the layout *height*, which re-lays-out Plotly to an unknown scale and leaves the px-sized word labels mismatched to the boxes (the true-to-scale text breaks). The single/animation/comparison plots go through `tabs._render_true_scale_chart`, which embeds the figure's own HTML at its exact pixel size and CSS-scales the whole block uniformly to the column width. Figure size is capped (`plots._DISPLAY_MAX_*`) so it fits a research display; PNG export bumps `scale` to stay crisp (SVG/PDF are vector). The embed loads plotly from CDN (needs network) and re-mounts each rerun. **VIZ-10 autoplay:** an animation built with `autoplay=True` stamps `fig.layout.meta` with the intent + per-frame duration (`plots.animation_autoplay_frame_duration`); `_render_true_scale_chart` (and `api.save_figure` for HTML) then emit a `Plotly.animate` kick-off via `to_html(post_script=…)` (`plots.animation_autoplay_post_script`) so the replay auto-starts *at the configured speed* — Plotly's own `auto_play` ignores `frame_duration`, so the figure is always built paused and the kick-off is layered on top.
- **Animation transport controls must not shrink the plot.** The animation figure has `scaleanchor="x", scaleratio=1`, so if Plotly's automargin reserves vertical space for the play/pause/restart buttons + time slider, the *whole* equal-aspect plot shrinks — and the word boxes then render smaller than the true-to-scale label font computed for `fitted_h`, so the text looks oversized (the "animation text too large" bug). Fix: all transport controls sit BELOW the plot in the bottom margin, and the figure is grown by `plots._CONTROLS_MARGIN_PX (+ _CONTROLS_SAFETY_PX)` so the plot region stays ≥ `fitted_h` (width-bound) — i.e. the same box size as the static `make_scanpath_figure`. If you move/resize those controls, re-check the box height matches the static plot (~0.28 font-to-box ratio on the demo).
- **The rail hosts one set of controls for THREE render paths** — see *Which viz settings apply in which render path* below. A control that the active mode's builder doesn't consume renders **disabled with a reason** (`controls._mode_gate` / `_gated_help`), never silently ignored. Disabling must never rewrite the setting: a disabled Streamlit widget keeps its key's value, so pass no `value=`/`index=` on a gated widget (deep links + Save & restore read those `global_*` / `single_*` keys, and a mode toggle must not clobber them).
- Annotations (favorites/tags/notes) live in `st.session_state`; on localhost/desktop, `persistence.py` mirrors them (plus uploaded datasets, mappings, and view settings) to the single-user local recovery cache. The shared cloud demo remains per-session. The 💾 Save & restore JSON stays the portable/shareable format. Annotation-based trial filters reflect a star/tag on the *next* rerun (the editor writes the store after the filter reads it).
